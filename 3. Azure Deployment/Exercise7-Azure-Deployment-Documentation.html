Exercise 7: Deploying a Deep Learning Model to Azure ML

Module 2: Deep Learning and Neural Networks
Duration: 60 minutes  |  Platform: Google Colab + Azure ML

What you will build: A trained Keras model deployed as a live REST API on Azure Container Instance. By the end, you will be able to send a JSON request and receive a real-time prediction in response.

1. Conceptual Overview

Training a model is only half the job. For a model to be useful in a product it must be reachable by other systems — a mobile app, a dashboard, or a downstream data pipeline. Azure Machine Learning handles this through a standardised deployment pipeline:

  Train model ──► Save model file ──► Register in Azure ML
                                              │
                                              ▼
  Test endpoint ◄── Deploy to ACI ◄── Write scoring script
                                       + Define environment
StageWhat happensOutput
TrainModel learns from data.h5 model file
RegisterFile versioned and stored in workspace blob storageModel object with name + version
Scoring scriptPython file that loads model and handles one prediction requestscore.py
EnvironmentSpecifies Python packages needed at inference timeConda/pip spec
DeployAzure packages everything into a Docker container and exposes a URLLive REST endpoint
TestSend JSON to the URL, receive predictionsJSON response

2. Prerequisites

  • Azure account with an active subscription (student free credit is sufficient)
  • Azure ML Workspace already created: ml-workshop-ws in ml-workshop-rg
  • config.json downloaded from Azure ML Studio and uploaded to Colab

How to download config.json

  1. Go to ml.azure.com and open your workspace
  2. Click the workspace name in the top-right corner
  3. Select Download config file
  4. Upload the file to your Colab session using the left-panel file browser
Never commit config.json to a public GitHub repository. It contains your subscription ID and workspace credentials.

3. Step-by-Step Guide

1Install the Azure ML SDK 
!pip install azureml-core azureml-sdk --quiet

Takes 2-4 minutes. The SDK lets you interact with Azure ML from any environment, including Colab.

2Connect to Your Workspace 
from azureml.core import Workspace
ws = Workspace.from_config()
print(f"Connected: {ws.name} in {ws.resource_group}")

Reads workspace details from config.json. A browser login prompt will appear on first use. Pass path="./config.json" explicitly if the file is not in the working directory.

3Train and Save the Model 
import tensorflow as tf, numpy as np, os

model = tf.keras.Sequential([
    tf.keras.Input(shape=(13,)),
    tf.keras.layers.Dense(16, activation="relu"),
    tf.keras.layers.Dense(8,  activation="relu"),
    tf.keras.layers.Dense(1,  activation="sigmoid")
])
model.compile(optimizer="adam", loss="binary_crossentropy", metrics=["accuracy"])
model.fit(X_train, y_train, epochs=20, validation_split=0.2)

os.makedirs("outputs", exist_ok=True)
model.save("outputs/heart_model.h5")

Write to outputs/ — Azure ML automatically captures anything in this folder as a run artifact.

4Register the Model 
from azureml.core.model import Model

registered_model = Model.register(
    workspace   = ws,
    model_path  = "outputs/heart_model.h5",
    model_name  = "heart-disease-classifier",
    description = "Binary classifier: heart disease from 13 clinical features",
    tags        = {"framework": "keras", "task": "binary-classification"}
)
print(f"Registered: {registered_model.name} v{registered_model.version}")

Each re-registration of the same name auto-increments the version. Version history enables rollback.

5Write the Scoring Script 
%%writefile score.py
import json, numpy as np, tensorflow as tf
from azureml.core.model import Model

def init():
    global model
    model_path = Model.get_model_path("heart-disease-classifier")
    model = tf.keras.models.load_model(model_path)

def run(raw_data):
    try:
        features    = np.array(json.loads(raw_data)["data"], dtype=np.float32)
        predictions = model.predict(features).flatten().tolist()
        return json.dumps({"predictions": predictions})
    except Exception as e:
        return json.dumps({"error": str(e)})

init() runs once at container startup and loads the model into memory. run() runs on every prediction request.

Critical: Load the model in init(), not in run(). Loading in run() reloads from disk on every call, adding 3-8 seconds of latency per request.
6Define the Inference Environment 
from azureml.core import Environment
from azureml.core.conda_dependencies import CondaDependencies

env  = Environment("heart-disease-inference-env")
deps = CondaDependencies()
deps.add_pip_package("tensorflow==2.10.0")
deps.add_pip_package("numpy==1.23.5")
deps.add_pip_package("azureml-defaults")   # required — do not remove
env.python.conda_dependencies = deps

Only include packages needed to run score.py. Avoid training-only packages (matplotlib, pandas) — they bloat the Docker image and increase deployment time.

7Create Inference Configuration 
from azureml.core.model import InferenceConfig

inference_config = InferenceConfig(entry_script="score.py", environment=env)

Bundles the scoring script and environment into a single deployable object.

8Deploy to ACI 
from azureml.core.webservice import AciWebservice

aci_config = AciWebservice.deploy_configuration(cpu_cores=1, memory_gb=1)

service = Model.deploy(
    workspace         = ws,
    name              = "heart-disease-api",
    models            = [registered_model],
    inference_config  = inference_config,
    deployment_config = aci_config,
    overwrite         = True
)
service.wait_for_deployment(show_output=True)
print("State:", service.state)
print("URL  :", service.scoring_uri)

Deployment takes 5-10 minutes. show_output=True streams logs in real time. If service.state is not Healthy, call service.get_logs() immediately.

9Test the Endpoint 
import requests, json

payload  = json.dumps({"data": [[63,1,3,145,233,1,0,150,0,2.3,0,0,1]]})
headers  = {"Content-Type": "application/json"}
response = requests.post(service.scoring_uri, data=payload, headers=headers)

print(response.status_code)   # 200 = success
print(response.json())        # {"predictions": [0.73]}

A successful call returns HTTP 200 with a JSON body. Values are sigmoid probabilities; >= 0.5 means the model predicts heart disease.

10Clean Up 
service.delete()
print("Service deleted")
Always run this before closing. A running ACI endpoint charges by the hour regardless of whether it receives any requests.

4. Deployment Checklist

  • [ ] config.json uploaded and workspace connection successful
  • [ ] Model saved to outputs/ before registration
  • [ ] score.py has both init() and run()
  • [ ] Model loaded inside init(), not run()
  • [ ] azureml-defaults included in pip packages
  • [ ] service.state == "Healthy" before testing
  • [ ] Test request returns HTTP 200 with correct predictions
  • [ ] service.delete() called after exercise

5. Troubleshooting

SymptomLikely CauseFix
AuthenticationException Config not found or expired login token Re-upload config.json; re-run Workspace.from_config() and complete browser login
Deployment fails after 10 min Error inside scoring script or missing package Run print(service.get_logs()) and read the Python traceback
ModuleNotFoundError in container logs Package missing from environment definition Add to CondaDependencies and redeploy
HTTP 500 from endpoint Runtime error inside run() Add try/except in run() returning str(e); check logs
HTTP 400: bad input JSON structure does not match what run() expects Print raw_data inside run() to inspect what arrives
service.state == "Failed" Docker image build failed Run service.get_logs(); often caused by incompatible package versions

6. ACI vs AKS: When to Use Each

Azure Container Instance (ACI)Azure Kubernetes Service (AKS)
Use caseTesting, dev, low trafficProduction, high traffic, SLA requirements
ScalingManual, single containerAuto-scaling across multiple nodes
CostLow (pay per container-hour)Higher (cluster always running)
